# Автоматизация отчёта по мастерам

Python-приложение для обработки Excel-файла с заказами и формирования итогового отчёта по мастерам.

Приложение:

* загружает исходный Excel-файл;
* проверяет структуру входных данных;
* нормализует даты, суммы, статусы, ФИО, города, рекламации и фото;
* обнаруживает некорректные строки и дубликаты ID;
* формирует статистику по каждому мастеру;
* сохраняет результат в `report.xlsx`;
* записывает события и ошибки в `app.log`;
* отправляет Telegram-уведомление после успешного формирования отчёта;
* предоставляет веб-интерфейс на FastAPI для загрузки исходного файла и скачивания готового отчёта.

## Технологии

* **Pandas** — чтение и обработка Excel-данных
* **OpenPyXL** — формирование итогового Excel-файла
* **FastAPI** — веб-интерфейс
* **Requests** — отправка Telegram-уведомлений
* **Uvicorn** — запуск FastAPI-приложения
* **python-dotenv** — загрузка настроек из `.env`

## Настройка Telegram

Для отправки уведомлений необходимо создать файл `.env` в корне проекта:

```env
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=id_чата
```

Где:

* `TELEGRAM_BOT_TOKEN` — токен Telegram-бота;
* `TELEGRAM_CHAT_ID` — идентификатор чата, в который будут отправляться уведомления.

## Установка

Клонировать репозиторий и перейти в каталог проекта:

```bash
git clone <ссылка-на-репозиторий>
cd <название-проекта>
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать виртуальное окружение.

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Создать `.env` с настройками Telegram.

## Способы запуска

### 1. Запуск обработки локального Excel-файла

Для обработки файла, расположенного в `input_data`, из корневой директории проекта выполните:

```bash
python -m app.main
```

После успешной обработки в корне проекта будет создан файл:

```text
report.xlsx
```

Также будет записан файл:

```text
app.log
```

После формирования отчёта приложение отправит Telegram-уведомление:

```text
✅ Отчёт успешно сформирован
```

### 2. Запуск веб-интерфейса

Запуск FastAPI:

```bash
uvicorn app.web:app --reload
```

После запуска веб-интерфейс доступен по адресу:

```text
http://127.0.0.1:8000
```

Через веб-интерфейс можно:

1. выбрать исходный Excel-файл;
2. загрузить его;
3. запустить обработку;
4. получить готовый `report.xlsx`.
5. получить уведомление в Telegram


## Обработка данных

Входной файл должен содержать следующие обязательные колонки:

```text
ID заказа
Статус заказа
Дата
Сумма
Мастер
Город
Рекламация
Фото загружено
```

После обработки формируется два листа.

### Лист «Отчёт»

Для каждого мастера рассчитываются:

* количество выполненных заказов;
* сумма выполненных заказов;
* количество рекламаций;
* процент рекламаций;
* количество заказов без фото;
* количество отменённых заказов.

### Лист «Ошибки»

Содержит строки, которые невозможно корректно использовать для формирования статистики.

Для каждой ошибочной строки сохраняются исходные данные, причина ошибки и номер строки в исходном Excel-файле.

## Принятые решения

### 1. Анализ исходных данных

Перед реализацией обработки был проведён анализ исходного Excel-файла.

Для каждого поля были определены:

* корректные значения, которые не требуют изменений;
* варианты написания и опечатки, которые можно однозначно нормализовать;
* значения, которые невозможно корректно обработать и необходимо вынести в ошибки.

Правила нормализации построены на основании обнаруженных в исходных данных случаев и требований тестового задания. Ручное исправление исходного файла не выполнялось.

### 2. Обработка дубликатов ID

**Решение:** Все строки с дублирующимся ID заказа выносятся в лист «Ошибки» с причиной `Дубликат ID заказа`.

**Обоснование:** Невозможно определить, какая из записей является корректной. Безопаснее исключить все дубликаты, чем использовать потенциально некорректные данные и допустить двойной учёт заказа.

### 3. Рекламации

**Решение:** Рекламации учитываются только для заказов со статусом `Выполнен`.

**Обоснование:** Рекламация относится к результату выполненной работы. Для отменённых, новых или перенесённых заказов рекламация не учитывается.

### 4. Процент рекламаций

**Решение:** Процент рекламаций рассчитывается как отношение количества рекламаций по выполненным заказам к количеству выполненных заказов. Если выполненных заказов нет, процент равен `0`.

**Обоснование:** Показатель отражает долю выполненных заказов, по которым была рекламация.

### 5. Заказы без фото

**Решение:** Заказы без фотографии учитываются для всех статусов.

**Обоснование:** В ТЗ не указано ограничение по статусу заказа. Поэтому учитываются все корректные записи, в которых поле `Фото загружено` имеет значение `Нет`.

### 6. Нормализация данных

**Даты:** Поддерживаются обнаруженные в исходном файле форматы `ДД.ММ.ГГГГ`, `ГГГГ/ММ/ДД`, `ДД-ММ-ГГГГ`, а также даты с русскими названиями месяца (`мая`, `май`). Некорректные календарные даты попадают в ошибки.

**Суммы:** Обрабатываются числовые значения, пробелы, обозначения валюты (`₽`, `руб.`) и запятая в качестве десятичного разделителя. Некорректные и отрицательные значения попадают в ошибки.

**Статусы:** Значения приводятся к каноническому виду. Известные варианты написания нормализуются, например `Закрыт` → `Выполнен`, `ОТМЕНА` → `Отменен`, `Отказ клиента` → `Отменен`. Неизвестные и неоднозначные значения попадают в ошибки.

**ФИО:** Удаляются лишние пробелы и нормализуется регистр. Пустые значения попадают в ошибки.

**Рекламация / Фото:** Значения `да`, `yes`, `1` приводятся к `Да`, значения `нет`, `no`, `0` — к `Нет`. Неизвестные значения попадают в ошибки.

**Города:** Удаляются лишние пробелы, известные опечатки и варианты написания исправляются через словарь соответствий.

## Логирование

Основные этапы обработки записываются в `app.log`.

В лог попадают:

* начало обработки файла;
* количество загруженных строк;
* количество найденных дубликатов;
* количество корректных и ошибочных строк;
* статистика по типам ошибок;
* количество мастеров в итоговом отчёте;
* успешное создание отчёта;
* результат отправки Telegram-уведомления;
* ошибки обработки.
